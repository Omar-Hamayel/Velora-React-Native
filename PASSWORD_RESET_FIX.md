# Forgot-password browser fix

26 October 2026. Root cause confirmed in the installed react-native-web Alert implementation: Alert.alert() is empty. WelcomeScreen used it for successful forgot-password and resend-confirmation actions, so successful HTTP requests produced no visible browser feedback. Local runtime also uses a loopback SMTP sink, not external email delivery. The backend intentionally sends reset mail only for existing, active, confirmed accounts and returns the same neutral response otherwise.

Fixed in existing files: WelcomeScreen.tsx uses localized, visible inline success feedback, clears stale errors/success state before requests and localizes the sending state. ErrorBanner.tsx supports an optional success tone, retaining its default error behavior. No backend/auth/AI endpoint, credential, token-validation policy or mail-delivery provider was changed. No real user's password was modified.

Added tests/e2e/password-reset.spec.ts. Three real local browser/HTTP/Identity scenarios passed: English and Arabic request feedback, actual captured reset mail, usable existing reset-password.html, successful password update, old password rejected, new password login accepted, replayed reset token rejected; unknown/unconfirmed requests remain neutral and send no reset mail. The tests create only synthetic *@example.invalid accounts in the isolated local fixture.
